## 操作目标

1. 任意 Bitwig Audio track 跟随工程 BPM 正常录音，裁剪并选择一个 Audio Clip。
2. 将工程内 Clip 交给 Beat Lab，优先验证直接拖入，不让用户手动保存、寻找 WAV。
3. 插件显示来源、BPM、长度、波形；做起音检测、最多 A/B/C/D 四类分组、Review、量化、力度编辑。
4. 每类映射到 MIDI note；真正鼓音色由目标轨的 Drum Machine 等音源提供。
5. 把结果送回 Instrument track 成为普通 MIDI Clip，优先验证拖出；一键写入另行评估。

不需要固定名称的 input/drums 轨，不需要插件重新录音。Beat Lab 是转换编辑器，
不是另一个录音机，也不自带鼓库。下一版不以 Record/count-in/Save Take/Import WAV 为主流程。
软件可自动管理中间文件，但不能把文件管理负担转交用户。

## 已核实与边界

- Library 两个试验轨已由用户删除，本轮经界面确认并保存，不重建。源码与分析引擎保留。
- 本机 Bitwig 6.1.4 的 `Clip`、`CursorClip`、`ClipLauncherSlot`、
  `ClipLauncherSlotBank` 接口有音符编辑/空 Clip 创建能力；
  在这些接口中未发现所选 Audio Clip PCM/源文件读取能力，未据此断言所有其他接口均不可行。
- [官方 Sampler 文档](https://www.bitwig.com/sampler/)的拖入 Clip 能力属于内建设备，
  不能证明第三方 CLAP 能接收相同内容。
- [CLAP 稳定扩展](https://github.com/free-audio/clap/tree/main/include/clap/ext)
  没有通用工程 Clip 读写协议。宿主 BPM、MIDI 输出端口、写入编曲 Clip 是不同能力。
- **第三方插件实际收到的拖放载荷尚未验证。** 仅增加 JUCE 文件拖放不能证明可用。
  遇到 `.bwclip`/私有对象必须明确处理或拒绝，不能伪装成功。
- 即使收到源 WAV，也不能忽略 Clip 的裁剪、起点、循环、伸缩、多 Audio Event，
  直接分析整段源文件。不要默认解析私有 `.bwproject` 格式。

### 识别点太少（v0.3.1）

不用重录。先保留波形，降低 `Gate dB`（更负，例如 −36 → −42 → −45），然后点 `Reanalyze`。它重新分析同一段原始录音，保留 MIDI 映射/量化设置，但会替换手动修改过的节奏点；需要保留编辑时先备份工程。Gate 随工程保存。若噪声也被识别，回调到更高门槛。不要靠无限降低 Gate 或提高轨道推子补救；推子不修复这段已录音频。
