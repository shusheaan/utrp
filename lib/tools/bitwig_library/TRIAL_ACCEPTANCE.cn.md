## 目标与决策

2026-10-18 用户确认：重点不是穷举软件功能，而是验证录音、多次 take、音色设计、
高层控制面板、Grid 思路，以及 AI / 脚本 / 自研插件能否支持可重复的日常创作。
30 天是工作计划窗口；实际试用截止日期以账户及软件显示为准，不在此推算授权到期日。

主 DAW 决策条件：核心手动流程顺畅、保存恢复可靠、重要自动化可重复，且用户亲手认可。
不要求所有操作都能脚本化；不因为存在 CLAP 或 Controller API 就认定所有宿主操作可控。
试用期间保留 REAPER 工程作为对照，不提前删除。

状态：`- [ ]` 未验收，`- [x]` 已验收；软件测试和真人试用分开记录。
已有证据见 WRAPUP / GRID_LAB，不自动等价于以下端到端场景通过。

## P0：录音与重录，先确保不会丢创作

- [ ] MIDI：录实体键盘和 Chord Lab 输出；停止后回放与实际演奏一致，无卡音。
- [ ] Audio：真实吉他干声与效果监听分离；确认输入、监听、延迟和回授风险。
- [ ] 固定起点 / 范围：回到目标位置、预备拍、录指定小节、停止和立即重录。
- [ ] 连续录至少 3 个 takes：验证该录音模式是否保留各遍，检查首尾、边界音符与尾音。
- [ ] Take 选择与编辑：分别验证 audio / MIDI 能做什么，选整遍或选片段；不假定二者功能相同。
- [ ] 重录 / 撤销：新 take 不意外覆盖唯一旧录音；误操作可恢复。
- [ ] 保存、关闭并重开：音频、MIDI、takes、编辑结果、插件与路由完整恢复。
- [ ] 用户亲手完成“准备 → 录一遍 → 重录 → 选最好一遍 → 保存”，记录实际步骤和不顺手之处。

真实吉他测试需要 Spark GO 和用户演奏。无人值守合成测试不能替代此项。

## P1：音色与统一控制面板

- [ ] 选一个 Surge 音色，将常用参数映射到一页 Remote Controls，界面命名全英文。
- [ ] 以 Brightness、Motion、Space、Attack、Release、Width、Drive、Output 为候选，
  按实际音色删改；记录每个宏对应的目标参数、范围与方向，不强行凑 8 个。
- [ ] 验证一个宏控制多个参数时的上下限、音量跳变、自动化录写和回放。
- [ ] 分别保存工程状态、可复用 preset 与映射；关闭重开并在新工程加载，核对哪些被保存。
- [ ] 保存 A / B 音色与相同 MIDI 的音频对照；比较时记录响度差，避免仅因更响而误判。
- [ ] 用户只用面板就能完成一次音色变化，不必反复寻找插件内部参数。

## P2：Grid，理解规则而非背模块

- [ ] 用现有 Warm Fractal Veil 解释声源、时间、音高、动态、空间与输出各部分。
- [ ] 做一个小型可理解的生成式变体：约束音集、稀疏触发、慢调制；每个新增模块说明目的。
- [ ] 对比固定循环、概率变化与音色调制；区分“声音变化”与“产生新的 MIDI 音符”。
- [ ] 暴露少量高层宏，验证范围安全、停止与重新启动行为、CPU 和保存恢复。
- [ ] 保存可玩的工程 / preset、短音频和结构说明，让用户能自行修改一处并听出结果。

现有 Grid 示例已有保存重开和音频技术检查；主观听感和本清单教学场景仍待验收。

## 横向：AI、脚本与自研插件

- [ ] 对每个关键动作标记实现层：原生 UI、Controller API、GUI 自动化、自研 CLAP、不可行 / 未验证。
- [ ] 选轨、改宏、启动 / 停止、录音与保存分别确认可访问接口及限制，不把鼠标脚本当稳定 API。
- [ ] 自动化改动可撤销 / 恢复、有日志；涉及音量或录音文件时有安全边界。
- [ ] 同一自动化流程连续运行 3 次，记录成功率、焦点 / 弹窗依赖和失败后的恢复方法。
- [ ] Chord Lab / Guitar Frontend 的 state、宿主重开、混合输入与焦点快捷键做目标场景回归。
- [ ] 只有明确缺口才加自研插件；先写出它解决什么问题，避免重造宿主已有功能。

## 节奏与保存规范

建议顺序，不是自动排程：

1. 第一阶段：P0 录音、重录与保存。
2. 第二阶段：P1 音色面板、automation、preset 复用。
3. 第三阶段：P2 Grid 与生成式结构。
4. 最后阶段：用一个短作品串联，复测薄弱项并决定是否主用 Bitwig。

每次测试都留下四样东西：**工程快照、操作记录、可听结果、结论与下一步**。

- 大文件拟放 `~/storage/daw/Bitwig Trial/<scenario>/`，不进 Git；该目录尚未因本清单创建。
- 项目及 clip / track / macro / preset 名字用英文。正式 Library 不作为破坏性测试场地。
- 文档、脚本、配置与测试源码放 UTRP；临时自动化证据放 `target/`，重要结论同步到文档。
- 阶段快照命名示例 `Recording-01-Baseline`、`Recording-02-ThreeTakes`、`Sound-01-A`。
- 不仅保存 .bwproject：检查外部音频、采样、插件版本与 controller 依赖；自动备份不是完整备份。

每条结果至少记录：日期、版本、输入设备 / buffer、操作步骤、预期 / 实际、证据路径、
手动或自动、是否用户亲测、剩余问题。未通过保持 unchecked，并注明原因。
