### 和声研究练习：已登记、待实现的范围

用户要求覆盖以下五项。本轮是 UI 首版，**下列专门练习都尚未完成，不因已有个别相似行为就标为支持**：

- [ ] Common-tone Harmony：从当前共同绝对音高奖励，扩展为明确的共同音约束/目标及验证；区分“偏好保留”与“实际保留”。现有基础在 `chordlab_game/game.rs` 的 `common_weight` 评分。
- [ ] Chromatic Voice Leading：显式约束目标声部的半音变化并记录声部对应；不能把所有就近移动或任意调外和弦称为半音练习。
- [ ] Planing：增加和弦结构/声部间距的平移规则与边界验证；区分严格半音平移和调内移动，不能只复用现有平均音区上行/下行开关。
- [ ] Modal Interchange：明确“同主音借用但不转调”的事件及来源调式。底层已有受 `extensions` 控制的平行小调 iv 借用，但游戏策略关闭该路径，且旧分支生成三和弦，不能直接当成全七和弦练习已可用。
- [ ] Pedal Point / Upper Structures：分别定义固定低音与上层和弦目标。实现前需解决现有四音密集七和弦、单手跨度约束与持续低音的关系，并决定持续低音由玩家还是伴奏承担；不悄悄丢低音或更改答案音数。

这些需求的实现应分别有生成不变量、具体音高、可读标签和预告一致性测试；此阶段不预先加入无效菜单。相关音乐风格是练习应用方向，不作为五种互斥分类。

- 上方改为 NOW / NEXT / THEN 三个**和声目标组**。每组显示已确定的接近链及实际解决目标；例如 `ii → V → iii`，前两项相对 iii 标记，最后一项保留本调 iii。链内每个和弦仍分别作答，白色描边仅指示当前实际题目；不是一组音同时判分。预告按 FIFO 提交，不能在显示后重新抽样。三组最多显示九个实际事件，转调解锁不会修改已提交的预告。
- 当前调胶囊黑底白字。未来组首次进入新调时显示白底黑字，成为当前后改黑；连续同调不重复显示。目标和弦复用左侧固定相对大调色板；**临时接近胶囊例外**，按目标根音为 I 的级数着色：ii 绿、V 橙；三全音替代的实际 bII 绿、相关 bvi 蓝，不将所有属功能都涂成 V 橙。最低音、八度及和弦内音级分行显示。

- 下方保留 Start/Restart、Pause/Resume、Play/Demo 秒数、转调概率、音区方向与接近开关，不新增高级设置。面板参数生效范围仍与下节一致。

## 0.3.4 候选版：七和弦练习策略（2026-10-23）

**仅源码与构建候选版，尚未安装或完成真实 Bitwig 验收。** 不修改 Library、音色、路由、controller 或窗口服务。风格化和独立版继续暂缓。

- 插件显式启用独立练习策略；终端模拟器保留原默认规则。从原固定闭环随机位置开始，不重复加权末尾与开头共享的 I。游戏目标、过渡、枢纽和到达和弦全部为完整七和弦；共同和弦转调必须共享七和弦，不能仅共享三和弦。
- 本次停留在当前调时，七个骨架级数都成功完成后才解锁自动转调。每个完整和弦可由任一乐器完成，但双方不能合并部分命中。超时、预告和临时接近不填充七级清单；转调到达的主和弦可计入 I。这里覆盖的是级数，不是所有转位或所有调外和弦。重新进入一个调会重置清单。
- 覆盖后在下一个安全规划边界检查，此后每四次合适的骨架规划机会检查一次，可配置。默认概率 50%；0% 关闭自动转调。不打断已经确定的接近链或解决；后两题锁定，因此解锁不会替换已显示的题目。旧的 40 题均衡容差**不是等待门槛**，只保留在返回目的调的资格判断中。
- 目的调均衡使用本局实际成功完成的目标数，不使用预生成题数。在可达调中优先选成功数最少的，并列随机。原有 20% 返回偏好可选择符合条件的上一个调，但仍受七级覆盖门槛约束，且避免连续返回。路线保留属七、共同七和弦和减七转调，在可用路线中抽取，不是无条件各占三分之一。
- Voicing 限定四音、密集排列、单手转位，范围 E2–A5，跨度最多 12 半音。和弦名加最低音及八度可唯一确定这一受限家族，不包含任意开放排列、无根或重复音爵士配置。胶囊增加**低音在和弦内部的级数**，如 `ii Dm7/F3(b3)`：根音 D，最低音 F，是小三度。普通模式保留三和弦、七和弦、九和弦和原吉他选择。
- 音区短句持续 4–8 题。Mixed 按可配置权重抽取 Hold/Rise/Fall，当前 1:1:1。优先减少排序后各声部的移动，奖励相同绝对音高，惩罚过度重复音高并加入有限随机扰动。Rise/Fall 约束平均音高方向，到可达边界反向；平均音高单步最多五半音。共同音保留是偏好，不保证每个共同音不动，也不意味着每个单独声部最多移动五半音。

## 规则

- 钢琴和吉他面对同一个紧凑钢琴 voicing；和弦名加最低音及八度唯一确定它。例如 `Em/G4` 是 G4–B4–E5，不是任意 Em 转位。
- 精确匹配 MIDI 音高，包括八度。可分解或同时弹；每方独立收集，不能拼凑双方命中。先独立弹完的一方获得速度分，完整回放后换题（公式见本页最新候选记录）。相同采样位置同时完成时，按宿主提供的事件顺序决定先后。
- 重复音不重复计分；下一题不继承上一题的持音。必须先松开再重新弹下。吉他只识别单音音高，不要求弦、品或把位。
- 默认每题 10 秒，可设 1–120 秒；超时不加分，展示答案并演示，默认 2 秒，可设 1–10 秒。修改时长从下一题生效；暂停保留剩余时间。
- 开始前和每题开始时隐藏键盘、指板、五线谱的答案。正确音出现后持续保留正常的和弦/调内颜色、轮廓和光晕；错音不显示为答案。答对和超时都显示全部目标音。
- 游戏中禁用自动电脑和弦和正常音型导航，避免一次命令直接完成答案。实体 MIDI、吉他检测和 S 延音控制仍可用。退出后正常电脑键盘控制恢复。

## 和声与 voicing

`../chordlab_game/game.rs` 直接复用 UTRP `Progression` 和原有 `config/simulate.toml` / `config/progressions.toml`，不复制和声算法、不启动服务。三/七和弦、转调、临时经过、恢复调来自原引擎；首版关闭扩展音与 ambient 模式。右侧显示当前调、当前和弦、原引擎原因和随后两个和弦。

独立 voicing 规划在 E2–A5 内选择紧凑排列，每个和弦跨度最多 12 半音；短句在保持/上行/下行之间切换。优先共同实际音、就近移动，平均音高变化最多 5 半音；方向受边界约束时转向。长期访问次数参与随机采样，避免总停在一个音区。具体限制和权重集中在 `../chordlab_game/game.toml`，随构建嵌入，不读取用户 cwd 配置。

## MIDI 路由

| 通道（1-based） | 用途 |
| --- | --- |
| 输入 1–14 | 钢琴计分，原 MIDI 发声/踏板路由保留 |
| 输入 15 | 吉他计分，仅显示/判定，不转成下游钢琴声音 |
| 输入 16 | 原电脑控制私有命令，不能用于答题 |
| 输出 16 | 游戏答案演示，独立 Note On/Off 与 CC64 Off |

Library 原有 Guitar Frontend 检测通道 2 经 Note Receiver 映射到 15 的设置继续使用。**演示输出 16 必须单独送到钢琴音源**，其他演奏通道照旧；不能仅因为有 MIDI 输出就声称已经接好钢琴。本次隔离测试没有音频设备，只验证演示事件与时间，不代表 Spark GO 检测精度、真实听感或 Bitwig 钢琴路由验收完成。

关闭游戏只清理自己的演示通道，不关闭实体键盘的音或踏板。进入游戏释放电脑自动和弦的所有权；退出不自动重弹进入前已释放的电脑和弦。用户在游戏中主动切换 S 属于用户操作，不会在退出时被偷偷撤销。

## 窗口与兼容

- **Bitwig 内只有既有 `../plugin_windows/layout.py` 负责位置**。通过 Bitwig 主窗口与 `transient_for` 关系识别归属后，插件只改变自身尺寸，不再保存、移动或恢复窗口坐标。G 展开/收起触发原程序按实际宽度重算中央组，避免两套逻辑互相抢位置。无需新服务；若原布局程序未运行，则不保证自动成组居中。
- 快速连点可能在两次轮询之间完成整轮开合，尺寸相同却已被宿主移位。因此每次开合结束用一个 `utrp-chordlab-layout-<revision>` Sway mark 请求重新布局；只替换自身的版本标记，不动用户 marks。布局程序将版本纳入 signature。插件和布局源码须配套更新，不能只换 CLAP。
- 原程序每 0.4 秒检查尺寸；这是最终稳定布局，不承诺宿主 resize 的每一帧都无过渡。手动拖动一直有效到下一次结构变化；G 收起后采用当时的正常居中布局，而非强制恢复旧坐标。屏幕不足沿用原程序的显式溢出提示，不承诺任意窗口组合都能放下。
- **非 Bitwig 的隔离/独立宿主**保留插件自身的 Sway 开合布局：只检查当前工作区 floating 窗口；同进程窗口可避让，无关窗口不移动。自动移动的窗口在收起时恢复，用户手动移动的窗口保留；空间不足报告错误。非 Sway 宿主不自动安排旁边窗口。
- Sway IPC 只在 G 切换的 UI 线程访问，不新增全局桌面规则。此次没有修改或重启真实桌面的既有布局服务。
- 稳定 CLAP ID `org.utrp.chordlab`、21 个参数和 v3 保存格式保持不变。游戏不写正常 sliders/音型记忆/序列化状态；音频线程不调用 Rust 规划或 Sway IPC。
