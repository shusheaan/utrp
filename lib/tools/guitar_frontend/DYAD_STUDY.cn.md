# 保守双音实验：不替换正式单音版本

[English](DYAD_STUDY.md)

## 目标与边界

2026-10-18：用户要求保留当前单音体验，先研究力度接近的两个音，覆盖吉他指板；暂不做三音。
本轮实现 **离线双音候选分析与回放工具**，不是已经可在 Bitwig 试弹的双音 CLAP。
没有修改/安装 Guitar Frontend，没有修改 Library、音色、单音参数或吉他只显示的路由。
即使离线成功，也不能称作真琴超低延迟或全指板识别已经验收。

## 实现与为什么不直接取最强两个频率

- `dyad_experiment.py`：因果 Hann 窗频谱，带插值的峰值提取；检查两个候选的基音强度接近、
  频率分离、谐波覆盖和候选歧义。每个音还需要至少两个不被另一个音解释的独立分音支持。
- 优先单个谐波系列的解释，包括基音缺失的情况。不把一个音的第二/第三泛音猜成双音。
- 连续两帧一致才输出；不确定立刻撤回双音候选，不延长已有输出制造“稳定”的假象。
- 这不是对现有单音识别器的简单叠加；后续整合必须设计单音/双音仲裁，不能同时输出互相矛盾的结果。
- 有意拒绝缺少独立谐波证据的纯正弦双音、很多八度/五度和分辨不开的低音近距离组合。
  真琴近似纯音或基音偏弱时也可能漏检；拒绝并不等于已经识别正确。
- `dyad_experiment.toml`：分析范围 E2–E6（MIDI 40–88），标准调弦、0–24 品；48/64 ms 窗、8 ms hop。
  这是实验范围，正式单音插件仍是原来的 MIDI 38–88。
- Python/NumPy/SciPy 实现会分配内存，**不能放入 CLAP 的音频回调**。它用于决定算法是否值得移植到固定缓冲 C++。

## 可复现测试

```sh
python -m pytest lib/tools/guitar_frontend -q
OPENBLAS_NUM_THREADS=1 python lib/tools/guitar_frontend/dyad_study.py \
  lib/tools/guitar_frontend/dyad_experiment.toml target/guitar-dyad-study
python lib/tools/guitar_frontend/dyad_replay.py \
  lib/tools/guitar_frontend/dyad_experiment.toml INPUT.wav START_SECONDS END_SECONDS OUTPUT.json
```

- `dyad_study.py` 枚举不同琴弦、各 0–24 品的音高对，去重为 **1,156 对**。
  包括不易按出的跨距，用来测音域而非推荐指法。同音弦去重后只有一个 MIDI 音高，不作为可区分的双音。
- 每对分别测试正弦与带谐波波形，两路归一化至相同 RMS。80 ms 前静音、160 ms 持音、80 ms 后静音；
  检查完整起音和止音过程，而不只抽稳态帧。任何错误音高对出现都将整个用例列为 wrong。
- 独立扰动组更换相位和谐波衰减，两个音分别偏移 ±12 cents，第二音幅度 0.85 倍，增加少量噪声。
  配置冻结后复测，但这些仍是合成测试，不能当作真琴独立数据集。
- 额外检查单音强泛音、缺失基音、静音、直流、噪声、非有限值、削波和少量不支持的三音。
  三音中有一个音被另一个音的泛音完全覆盖时，仍可能只输出其中两个；不承诺“所有三音必定空白”。
- 历史 A3 录音仅回放用户确认的前 38.2 秒，作为单音误报双音的筛查；后段乱弹不用于单音断言。
  录音 WAV 的非音频元数据引发 SciPy 警告，保留日志，没有吞掉异常。

## 首轮失败与修正

只用峰强度、谐波覆盖和两帧确认时，48 ms 全过程矩阵出现 **17 个误判用例**，尽管最初只看前两个完整帧时没有暴露。
主要是短窗内两个相近频率相互干扰，起音/止音时峰的位置移动。修正为每个音必须有独立分音支持，
而不是仅靠提高强度或 confidence。修正前记录保留在 `target/guitar-dyad-study/before-partial-check/`。
这是开发回归，不是可声称绝对正确的证明。

## 本轮结果与部署决定

以下是修正后的完整起止音检查；每列的分母均为 1,156 对。正确列表示持音期间至少确认一次正确双音且全段无错音，**不代表持续稳定率**；过晚列表示只在 160 ms 持音结束后才确认，不算成功。

| 信号 | 窗长 | 正确出现 | 错音 | 全程拒识 | 仅止音后才出现 |
|---|---:|---:|---:|---:|---:|
| 等 RMS 带谐波 | 48 ms | 817 | 0 | 329 | 10 |
| 等 RMS 带谐波 | 64 ms | 851 | 0 | 293 | 12 |
| 独立扰动组 | 48 ms | 860 | 0 | 292 | 4 |
| 独立扰动组 | 64 ms | 918 | 0 | 230 | 8 |

另有每档 1,156 对纯正弦双音全部拒识，这是独立泛音限制的明确代价。某些真琴音色也可能因为泛音太弱而被拒绝。
合成 D3＋G3 在两档都约 **56 ms** 首次确认；这是检测器观察窗口的延迟，不含接口、宿主、显示刷新和 Python 执行时间，不能承诺实弹同样快。
48 ms 的 A3 回放 4,770 帧、64 ms 的 4,768 帧均没有双音输出。64 ms 三音控制有一例输出真实音中的两音子集，故不能用本算法保证拒绝一切三音/扫弦。

85 项 Guitar Frontend pytest、项目相关合计 647 项 pytest、原单音 2 项 CTest 通过。这些通过表示代码回归正确，不意味着算法覆盖率已达标。
已核对正式 `Guitar Frontend.clap` 与 `Library.bwproject` SHA-256 前后相同。结果在 `target/guitar-dyad-study/`，
最终机器可读结果为 `summary.json` 与 `48ms.json` / `64ms.json`；日志保留修正计分前的记录，late-only 从 abstain 中单独拆出，不改检测输出。

**决定：保留离线实验，不部署为日常 CLAP。** 真琴双音录制待用户就绪；单音继续可用，未修改当前桌面或音频路由。

## 2026-10-18：Spark GO 空弦 D/G 首次实录

录音与分析保存在 `target/guitar-dg-validation/`：`dg-open-01.wav`、
`routing-01.txt`、`analysis-01.json` 与 `analysis-01.log`。从 Spark GO capture 直接另接录音支路，
没有录电脑麦克风，也没有改变原有 Bitwig 链路。WAV 解码得到完整 60 秒、48 kHz、mono float32；
峰值 −17.06 dBFS，无非有限值或削波样本。`pw-record` 退出码为 1，日志为空，原因未定位；
不能声称采集进程正常退出。SciPy 的非音频 chunk 警告保留，音频数据可解析；没有测量丢帧或端到端延迟。

前段 5.40–24.77 秒共 8 个自动分割的拨奏段，频谱可见约 147 / 196 Hz 及相应泛音，
与要求的 D3/G3 相符。后段约 36 秒后出现其他音高，未得到用户演奏标签，**不算 D/G 验收样本**。
没有根据这次录音修改检测参数。

| 窗长 | 8 段中至少出现正确双音 | 这些段内错误双音帧 | 稳态正确帧 / 全部稳态帧 | 首次确认范围 |
|---|---:|---:|---:|---:|
| 48 ms | 8/8 | 0 | 807/1126（71.7%） | 64–676 ms |
| 64 ms | 8/8 | 0 | 810/1126（71.9%） | 72–668 ms |

稳态只是自动剔除每段前 150 ms、后 100 ms 的评估窗口，不是人工逐帧真值。
首次确认从 10 ms RMS 门限起点计时，不是精确拨弦时刻，也不含设备/宿主/UI 延迟。
两档均有 4/8 段较快确认，另 4 段需约 0.49–0.68 秒；后续仍有拒识空白。
因此结论是 **真实 D/G 双音可以被正确识别，但快速、持续稳定的要求尚未达标**，
不能把 8/8 至少出现一次说成 100% 实时准确。正式单音插件与 Library 不变，不部署双音实验。
