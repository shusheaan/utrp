# Score Skeleton

面向已内化指板图的演奏者：把具体作品压缩为可听、可定位、可迁移的乐句骨架，而不是逐音复述 TAB。用户的乐器、定弦、理论背景和目标优先；不默认每位用户都懂 CAGED。

## 先锁定材料

- 确认作品、演奏者、版本和具体声部。`feat. X` 的文件名不等于谱中含有 X 的 solo；打开后核对标签、页码和小节范围。
- 优先查用户已有的 `sheets/` 和用户指定库，避免重复购买。只有用户需要找资源／外部校验时才检索官方商店、原作者演示和针对性教程；区分演示、慢速演示、带谱转录与真正的讲解课。
- `pdfinfo` 检查页数；`pdftotext -layout` 只用于定位。用 `pdftoppm` 渲染目标段并视觉核查全部相关页；必要时放大裁切核对弦线。OCR 丢失弦线、延音和推弦时不得据其直接推导音高。
- 核对定弦、capo、移调、拍号、速度及速度单位。使用原谱的小节号，不把分析分段号当小节号。

## 证据分层

1. **谱面事实**：音高／弦品、节奏、重音、休止、技法及声部，附页码与小节定位。
2. **分析推断**：调性中心、和弦碎片、动机关系、张力／解决。写出能支持它的事实；有歧义时注明替代解释。
3. **教学提炼**：选择哪些音／节奏作为记忆锚点，如何分层练习。明确这是练习版，不是原谱的逐音再现。

伴奏声部为空、只有旋律或无 bass 时，不编造完整和弦循环／Roman numerals。相同 pitch collection 不等于相同和声功能；例如 A–C–E–F# 可描述为 Am6 或 F#m7b5 的音集合，不能仅凭这四音判定实际低音或根音。不要把未听过的音频或未看过的视频写成已核对。

## 分析顺序

### 1. 全局地图

- 区分谱面调号、旋律音集合、工作调性中心和实际和声。没有调号不等于 C major。
- 找出稳定落点与反复使用的三和弦／五声音阶；再解释增加的调内音、半音接近、blue notes、推弦音程和摇把变化。
- 临时升降号不自动意味着转调；长时值的非调内音也不能一概丢为“无关经过音”。
- 若和声有证据，给 chord progression + 功能 + 各句目标 chord tone；缺证据则给可验证的旋律材料和待核实项。

### 2. 乐句压缩

按动机、呼吸、节奏、音区和终止点划分，不机械地每两小节切段。每句回答：

`定位 → 音乐作用 → 所在指板区域／弦组 → 和弦音锚点 → 材料与连接操作 → 落点／节奏 → 练习版`

- 区分同一乐句重复、移位重复与真正的新材料。
- 区分 arpeggio（和弦音展开）、scale run（级进）、sequence（音型模进）、double-stop voice leading（双音声部进行）、octave displacement（八度移位）。快不等于琶音；滑动双音不等于经过每个位置都换和弦。
- 先给原谱确有的音型，再给便于记忆的名称，避免概念堆砌。

### 3. 指板锚点

- 采用明确标记：`D5` = 第 4 弦 D 弦第 5 品；`e` 专指高音 E 弦，`E` 专指低音 E 弦。改变定弦时更新约定。
- 每个主要区域给少量根音／3rd／5th／7th 锚点、弦组及形状；区分实际弹出的 voicing 和用于定位的补全形状。
- 给连通路线：从哪处和弦碎片，经何种操作，到哪个目标音／新把位。不要给一整张与作品无关的音阶图。
- 用定弦 + 品数独立复算代表性音高与音程，特别留意 G/B 弦的大三度关系。推弦分别记录起音和目标音，不把按弦音当成实际持续音。

### 4. 分层练习

- Layer 1：保留入口、落点、长音、重音与休止，唱出并弹出骨架。
- Layer 2：加双音／和弦声部，区分上声部旋律与下声部支撑。
- Layer 3：加级进连接、琶音、半音装饰与跨把位路线；连音组先独立计数再接回拍点。
- Layer 4：恢复 slide、bend、vibrato、bar、tapping、音色和动态。对构成主要旋律的推弦目标／节奏，从 Layer 1 就保留，不把“表情最后加”理解为删掉结构性音高。
- 验收用可观察行为：不看谱指出落点、保留休止、从任一段启动、能说明连接逻辑；速度只是最后的维度。迁移练习使用改写的节奏／连接，不声称是原作。

### 5. 图文一体的指板矩阵

- 用户需要直观理解时，在相应乐句说明内嵌横向矩阵，不只提供独立图片目录。顺序为：一句骨架 → 局部图 → 如何移动／落点 → 简短练法。
- 用确定性的 SVG，不用 AI 生图排音符。现有脚本 `scripts/render_fretboard.py` 从 TOML 生成；实际范例在 `sheets/NLND_TABS/drown-matrices.toml`。从项目根目录执行：

  ```sh
  python scripts/render_fretboard.py sheets/NLND_TABS/drown-matrices.toml --output sheets/NLND_TABS --force
  ```

- 默认高音 e 在上、低音 E 在下，品数向右增长；6 弦定弦 MIDI 可配置。`auto_scale = true` 枚举所选音集的所有位置；`anchors` 则只突出指定的句子路标，灰色背景位置不是演奏指令。
- 一张图只解释一个概念，局部 2–14 品宽，通常 6–10 品即可；复杂路径拆图，不把全 solo 箭头叠在一张图上。
- 颜色表示相对于本图参照音的角色：1、b3/3、5、其他音；音名与级数同时保留，不只靠颜色。改变参照音必须显著标注，不能把“参照 A 的材料”偷换成“伴奏和弦是 Am”。
- 箭头只表示移动方向，不承诺节奏；同列或同时声部的含义写入图注。谱面路线、完整音集地图和教学简化图要分清。
- SVG 可直接嵌 Markdown；需稳定展示中文时用本机 `rsvg-convert` 生成 PNG，须有中文字体。SVG 与 PNG 都是生成物，修改 TOML 后一起重生成。
- 生成后检查实际预览：字不被裁切，音点不重叠，箭头与所描述操作一致；运行 `python -m pytest -q tests/test_render_fretboard.py` 检查音乐不变量、边界和 CLI。

## 交付与存档

- 默认先在对话给紧凑总结；用户要求写盘时再写盘，无须额外等待批准，除非用户要求先 review。
- 项目约定：`sheets/<collection>/` 放谱源、`manifest.json` 和具名分析 notes。保留用户原文件；复制时逐文件 SHA-256 校验，不覆盖不同内容的同名文件。只复制用户授权的材料，不默认批量分析整个收藏。
- notes 至少包含：来源／版本与范围、证据限制、全局地图、把位锚点、逐句结构表、节奏／表情、分层练习、待核实项。明确分析日期与哪些素材未核对。
- 私有谱不默认发布／提交；分析不能被称作官方讲解。临时渲染放 `/tmp`，避免污染资料库。
- 完成前复核：每个具体结论可回到谱页；音高复算；重复句对应正确；不把和弦形状误标为伴奏；复制数量／hash 正确；链接存在。

本项目实例：`sheets/NLND_TABS/drown-mateus-skeleton.cn.md`。仅在需要参考输出粒度时读它，不把该曲的调性、把位或练习分段套给其他作品。
